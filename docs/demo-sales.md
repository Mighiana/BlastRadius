# A three-minute customer demo

**Your Terraform diff shows what changed. BlastRadius shows what became reachable.**

Rehearse with the [generated customer sample](customer-samples.md).
Keep the baseline, candidate, blocking report, per-hop SARIF evidence and repaired
report open. All are synthetic, generated by the installed engine, and require no
AWS access. Use only genuine captures from the revision being shown.

## Three minutes

| Time | Show | Say |
|---|---|---|
| 0:00–0:20 | Baseline report | “Here is a small AWS Terraform configuration. This baseline has no new modeled blocking findings detected. That is a bounded analysis result, not a security certification.” |
| 0:20–0:40 | BEFORE/AFTER diff | “One line changes SSH ingress from a private CIDR to `0.0.0.0/0`. The rest of this candidate is identical. Terraform shows the edit; we want to understand its consequences.” |
| 0:40–1:00 | BLOCK and responsible change | “BlastRadius compares both configurations and returns BLOCK CHANGE under this policy. Here is the responsible CIDR change, one new critical path and one newly reachable sensitive bucket. The score is a heuristic, not a probability.” |
| 1:00–1:45 | Path and evidence for each hop | “The public SSH rule reaches this security group. The instance explicitly attaches it. The instance profile connects compute to this role, conditionally on compromise and credential access. The role's policy allows modeled S3 reads. The bucket is tagged sensitive. These five links explain why the one-line change matters. We have not proved routing, an SSH exploit, effective IAM permission or data theft.” |
| 1:45–2:10 | Generated remediation patch | “The supported local patch narrows SSH back to the sample's private CIDR. Your team would choose its actual approved access design. Downloading this patch changes nothing in AWS; review it as Terraform.” |
| 2:10–2:30 | Rerun: risky → repaired | “We re-analyze the repaired candidate. The new critical path is removed. No new modeled blocking findings detected. Review coverage as well as the decision; a high score does not settle unknown relationships.” |
| 2:30–2:50 | Reviewed GitHub Actions workflow | “The same comparison can run on a Terraform PR and leave a summary, artifacts and, when permitted, a bot comment. The reporting job treats candidate files as data. Preserve failing exits and use `--fail-on-review` for a strict gate.” |
| 2:50–3:00 | Sample outputs / question | “Would this evidence change how you review a recent Terraform PR? Where would the missing model coverage prevent you from relying on it?” |

For the GitHub step, open the [documented workflow](github-actions.md) and
[copyable configuration](github-action.yml); do not publish a live comment during
a rehearsal. The historical Actions example and the operator-managed
[GitHub App](github.md) have different acceptance histories. Do not describe
the App as a verified hosted installation or show a fabricated check.

## Sixty seconds

“Your Terraform diff shows what changed. BlastRadius shows what became reachable.
This synthetic change opens SSH to the internet with one line. The analyzer
returns BLOCK because that rule connects a security group to EC2, its attached
role, and a bucket classified as sensitive. Every hop has source evidence.

“These are modeled connections, not proof of an exploit. Routing and effective
IAM controls still need review. The suggested patch narrows SSH locally; it does
not apply infrastructure. We rerun the repaired candidate: no new modeled
blocking findings detected. A strict CI gate also fails REVIEW results rather
than treating incomplete analysis as approval.

“You can take Markdown, JSON and SARIF evidence into your PR review. What would
you need to see before using that decision?”

## Fifteen seconds

“Your Terraform diff shows what changed. BlastRadius shows what became reachable:
modeled paths from a changed AWS resource toward sensitive data, with evidence
for each hop. Review the proposed fix and rerun before merging. It is bounded
static analysis, not proof of infrastructure safety.”

## Presenter boundaries

Use the CLI's existing `SAFE TO MERGE` label only when showing actual output;
describe it as **“No new modeled blocking findings detected.”** Never claim “your
infrastructure is secure,” all-AWS coverage, zero false positives, automatic AWS
remediation, verified production readiness, live App acceptance, or a security
certification. If analysis is incomplete, show the diagnostics and strict REVIEW
failure. If an operation fails, say it failed and keep the failure visible.
